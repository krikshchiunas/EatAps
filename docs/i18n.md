# Мультиязычность EatAps

Семь языков: русский (исходный), английский, немецкий, испанский, португальский
(Бразилия), турецкий, арабский (справа налево). Документ описывает то, как
устроено сейчас, — с путями к файлам. Если что-то здесь разошлось с кодом,
прав код, а документ надо поправить.

## Быстрые команды

```bash
npm run i18n          # AST-проверка исходников + тесты словарей, данных, поиска, ИИ
npm test              # все юнит-тесты
npm run build         # сборка; падает, если язык выпал из офлайн-кэша
npm run test:e2e      # 7 языков × 4 размера экрана, RTL, офлайн, жизненный цикл
npm run test:visual   # снимки ключевых экранов
npm run verify        # всё перечисленное подряд — «ворота» перед продом
```

E2E и снимки работают по production-сборке (`vite preview`), поэтому перед ними
нужен `npm run build`. CI (`.github/workflows/ci.yml`) запускает всё это на
каждый push и PR.

## Реестр языков

`src/locales/registry.js` — единственный список языков. Запись:

```js
{ code: 'pt', name: 'Português (Brasil)', englishName: 'Portuguese (Brazil)',
  dir: 'ltr', intlLocale: 'pt-BR', matches: ['pt', 'pt-*'], enabled: true }
```

- `code` — ключ в хранилище и имя папки словарей. Менять нельзя: он записан у людей.
- `matches` — теги устройства. Точный тег сильнее совпадения по основе, поэтому
  `pt-PT` можно добавить отдельной записью (`matches: ['pt-PT', 'pt-AO']`), не
  трогая бразильский.
- `intlLocale` — для `Intl` (числа, даты, множественное число). У арабского
  `ar-u-nu-latn`: латинские цифры, как в вводе и на этикетках.
- `name` — на самом языке: так он показан в списке языков.

Из реестра читают: `src/lib/i18n.js`, загрузочный скрипт в `index.html`
(плагин `scripts/vite-plugin-i18n-boot.mjs`), проверка офлайн-кэша
(`scripts/inject-precache.mjs`), промпт ИИ (`src/lib/aiPrompt.js`), тесты и E2E.

## Как выбирается язык

1. Сохранённый язык (`localStorage['eataps:lang']`) — главнее всего. Сохраняется
   и выбранный вручную, и определённый при первом запуске. Значение читается
   терпимо: `de`, ` DE `, `de-DE`, `{"code":"de"}` → `de`; мусор → игнор.
2. Установка старше языков (есть данные `eataps:v1` / `eataps:state:*`, а языка
   нет) — русский: человека не переключают посреди привычного дневника.
3. Первый поддерживаемый язык из `navigator.languages` (`de-AT` → `de`).
4. Иначе — английский (французское, итальянское, польское устройство).

Функции выбора (`matchLanguage`, `readStoredLanguage`, `detectLanguage`…) лежат
в реестре и написаны на ES5: плагин сборки встраивает их **исходный код** в
`index.html`. Поэтому `<html lang dir>` выставляются до загрузки приложения той
же функцией, что использует приложение, — арабский не мелькает слева направо,
немецкий не мелькает английским (это проверяет `e2e/lifecycle.spec.mjs`).

Если пакет языка не загрузился (первый запуск без сети): показывается английский,
если нет и его — вшитый русский; определённый язык при этом сохраняется, и
следующий запуск с сетью откроется на нём.

`setLang(code)` защищён от гонок: применяется последний выбор, в каком бы
порядке ни пришли пакеты. Смена языка не перезагружает страницу и не сбрасывает
экран: меняются тексты, `lang`/`dir`, форматы чисел и дат.

## Словари интерфейса

- `src/locales/<код>/*.js` — группы строк (`common`, `day`, `add`, `stats`,
  `supps`, `social`, `settings`, `ai`, `system`, `progress`), склеиваются в
  `src/locales/<код>.js`. Русский вшит в основной бандл, остальные — ленивые
  чанки.
- `t('раздел.ключ', { n })` — строка с подстановкой. Множественное число — объект
  с категориями `Intl.PluralRules` (`one`, `few`, `many`, `other`; у арабского ещё
  `zero`, `two`) и параметр `count`.
- Нет строки в языке — подстраховка русским; нет и там — ключ (до этого не
  доходит: тесты требуют совпадения ключей).
- Никаких `t()` на уровне модуля: подписи в справочниках — геттеры (`get label()`).
- `fmtNum`, `fmtDate`, `fmtTime` — формат по `intlLocale`. Пустое и не-число →
  пустая строка, а не «0»/«NaN».
- `src/locales/<код>/boot.js` — тексты аварийного экрана (встраиваются в
  `index.html` при сборке; нет файла — сборка падает).
- `src/locales/glossary.js` — термины (белки, углеводы, добавки, порция…) по
  языкам, запрещённые варианты и заимствования, законно совпадающие с английским.

## Данные: стабильные id

Продукты, способы приготовления, порции и виды алкоголя имеют постоянные id:
`food_oatmeal`, `method_boiled_f`, `portion_glass`, `alcohol_vodka`. Добавки
(`suppId`) и нутриенты (`vitD`) имели id и раньше.

- Названия на всех языках, **включая русский**, — `src/locales/<код>/data/<таблица>.js`
  по id. Русское — исходное.
- В дневнике у записи хранится каноническое русское `name` (его читают старые
  версии и синхронизация) и, у новых записей, `foodId`/`methodId`
  (`withCatalogRef` в `src/lib/catalog.js` пересчитывает их при каждой записи и
  правке).
- Старые записи без id узнаются по названию: `catalogId('foods', 'Овсяные хлопья
  сухие')` → `food_rolled_oats_dry`. Другие написания, уже попавшие в дневники, —
  в `src/data/legacyNames.js` (строки оттуда не удаляются).
- Показ — `foodName(name)` / `entryName(entry)`: каталожное название → на языке
  интерфейса, «Название, способ», «Название 2.5%» — по частям, своё название
  человека — как записано. Название главнее id: переименованная запись не
  показывается чужим именем.

### Добавить продукт в базу

1. Строка в `src/lib/foods.js` (русское название и цифры).
2. id и названия на всех языках: `src/locales/<код>/data/foods.js`
   (`food_<английское_название>`). Тест `i18nQuality` укажет каждый язык без перевода.
3. При желании — синонимы в `src/lib/search/aliases.js`.

## Поиск

`src/lib/search/`:

| Файл | Что |
|---|---|
| `normalize.js` | регистр, диакритика, ß→ss, ı/İ→i, арабские огласовки/татвиль/алиф/та марбута, арабские и персидские цифры, пунктуация, дефисы, апострофы; лёгкий стемминг; транслитерация кириллица↔латиница; не та раскладка (`jdczyrf` → «овсянка») |
| `engine.js` | индекс (поля, токены, основы, словарь слов) и тиры релевантности, нечёткое сравнение (Дамерау-Левенштейн с порогом по длине слова) |
| `aliases.js` | синонимы продуктов по id и языку |
| `keywords.js` | наборы ключевых слов по id (латиница без умлаутов и т. п.) |
| `synonyms.js` | разговорные формы русского для расширения запроса |
| `names.js` | ленивый чанк: названия продуктов и добавок на всех языках |
| `index.js` | публичный API: `searchItems`, `matchCatalogFood`, кэш индексов |

- Поиск идёт по всем языкам сразу при любом языке интерфейса.
- Тиры (сверху вниз): точное совпадение → без пробелов → главное слово (первое в
  ru/es/pt/ar, последнее в en/tr: «milk» ставит овсяное молоко выше молочного
  шоколада) → начало поля → все слова → начала слов → основы → подстрока → часть
  слов → опечатки → звучание. Синоним ×0.9, слово-ключ ×0.8, вариант запроса
  (раскладка, разговорная форма) — по своему весу. Личная надбавка поднимает
  только внутри тира. Последний ключ сортировки — id: порядок детерминирован.
- Одна карточка на id: синонимы одного продукта не дают дублей.
- Индекс строится один раз на список и язык (WeakMap), версия — `INDEX_VERSION`;
  на нажатии клавиши ничего не нормализуется заново. Нечёткий проход идёт, только
  если строгих совпадений мало или ни одно не покрыло все слова запроса.
- `names.js` грузится в фоне после старта и кэшируется для офлайна; до его
  прихода ищется по русскому и языку интерфейса.
- «Возможно, вы искали…» (`add.didYouMean`) — когда выдача держится на исправлении.

### Добавить синоним

`src/lib/search/aliases.js`: `food_<id>: { de: ['Haferbrei'], … }`. Правила
(проверяются тестами): только существующий id; синоним означает **тот же**
продукт (не «молоко» для овсяного молока); одно слово — один продукт; опечатки
не пишутся — их прощает нечёткий поиск.

### Свои продукты

Своё (`source: 'custom'`), рецепты и шаблоны ищутся только по своему названию и
никогда не переводятся и не склеиваются с продуктом базы.

## ИИ

- Клиент отправляет `lang` (код языка интерфейса). Сервер (`buildSystemPrompt`)
  вставляет в промпт название языка **из реестра** — присланная строка в промпт
  не попадает.
- Правило в промпте: отвечать на языке последнего сообщения; если текста нет
  (только фото) или язык не понять — на языке интерфейса. Поля `reply`, `ask`,
  `name` карточек — на языке ответа. «Carrot» не переводится.
- Карточка → запись (`src/lib/aiCards.js`): точное совпадение названия или
  синонима на любом языке с ровно одним продуктом → каноническая запись с
  `foodId` (после смены языка показывается на новом). Иначе — название как у ИИ.
  Опечатки и «похоже на» совпадением не считаются. Цифры — всегда из карточки.
- Ошибки — по коду из словаря (`ai.err.*`), сообщение сервера человеку не
  показывается.

## RTL

- `dir` выставляется на `<html>` ещё до загрузки приложения и при смене языка.
- Вёрстка — логическими свойствами (`margin-inline-start`, `text-align: start`).
- Направленные значки: `‹ ›` зеркалятся сами (они bidi-mirrored), SVG-шевроны —
  через `[dir="rtl"] .set-chev`/`.rtl-mirror`, стрелки `← →` выбираются явно.
  Камера, поиск, сердце, логотипы, еда не зеркалятся.
- Листание дней зеркальное: следующий день слева.
- Юридические документы — немецкие и слева направо, пояснение к ним — на языке
  интерфейса.

## Офлайн

`scripts/inject-precache.mjs` после `vite build` читает манифест сборки и кладёт
в список предзагрузки service worker'а ядро, пакет **каждого** языка реестра со
всеми его общими чанками и индекс поиска. Чего-то нет — сборка падает. Сам
service worker (`public/sw.js`) отдаёт хэшированные файлы из кэша без учёта
`Vary`. `e2e/offline.spec.mjs` проверяет: офлайн-перезапуск на выбранном языке,
переключение на ни разу не загруженный язык, поиск без сети.

## Проверки

- `scripts/i18n/check-source.mjs` — AST-проверка (через `@babel/parser`): текст
  в JSX, пользовательские атрибуты (`placeholder`, `title`, `alt`, `aria-*`),
  фразы в `alert`/`setError`/…, кириллица и арабский в коде, неверные ключи
  `t()` (литералы и префиксы шаблонов). Исключения — только явные пометки с
  причиной: `// @i18n-data-file`, `// @i18n-model-prompt`,
  `// @i18n-fixed-language`, `/* @i18n-data */`. Коды единиц (`г`, `мл`) и
  сообщения разработчику (`console.*`, `log.*`) проходят сами.
- `src/lib/i18n*.test.js` — ключи, плейсхолдеры в каждой форме, кривые скобки,
  пустые строки, формы множественного числа на числах 0…1000, непереведённые
  копии (через глоссарий), термины, жизненный цикл языка, загрузочный скрипт.
- `src/lib/search/search.test.js` — каждое название каждого языка находится
  первым, сценарии, опечатки, нормализация, ранжирование, отрицательные случаи,
  детерминизм, скорость.
- `e2e/` — экраны на 7 языках и 4 размерах (переполнение, выход за край,
  обрезанные кнопки, сырые ключи, чужой язык, `lang`/`dir`, ошибки консоли),
  жизненный цикл, клавиатура, RTL, аварийный экран, офлайн, снимки.

Снимки (`e2e/visual.spec.mjs-snapshots/`) сняты со шрифтом DejaVu Sans и
фиксированным временем. После намеренной правки вёрстки:
`npm run build && npm run test:visual:update` — и проверить разницу глазами.

## Добавить язык

1. Запись в `src/locales/registry.js`.
2. Папка `src/locales/<код>/` (скопировать `en/`, перевести) и `src/locales/<код>.js`.
3. Загрузчик в `LOADERS` в `src/lib/i18n.js`.
4. Глоссарий в `src/locales/glossary.js`.
5. `npm run verify`: тесты назовут каждую непереведённую строку, продукт,
   добавку, форму множественного числа; сборка — если язык не попал в офлайн;
   E2E и снимки пройдут новый язык сами (список берётся из реестра; для снимков
   нового языка — `npm run test:visual:update`).
