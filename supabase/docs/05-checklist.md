# Чек-лист новой миграции

Проходить перед прогоном на живой базе. Каждый пункт — про ошибку, которая
здесь уже случалась; подробности по ссылкам в [`03-pitfalls.md`](03-pitfalls.md).

---

## До того, как писать

- [ ] Открыл [`catalog.md`](catalog.md) и посмотрел, как объект выглядит
      **сейчас**, а не в старой миграции
- [ ] Проверил, нужна ли вообще новая таблица, или данные — часть блоба
      `app_state` ([`01-model.md`](01-model.md#общий-принцип-local-first--один-блоб))
- [ ] Если трогаю доступ — свёл круги по
      [`02-access.md`](02-access.md#матрица-кто-что-видит) и понимаю, какой
      именно расширяю или сужаю

## Идемпотентность

- [ ] `create table **if not exists**`, `add column **if not exists**`
- [ ] Политики, триггеры, ограничения и представления — под `drop … if exists`
      **с тем же именем**, которое создаётся. Снять только старое имя мало (§26)
- [ ] `npm run sql:idem` проходит — сплошная проверка повторного прогона
- [ ] Ужесточаю CHECK на таблице с данными? Между `drop constraint` и
      `add constraint` стоит шаг приведения данных (§27)
- [ ] Функции — `create or replace`, а при смене набора колонок сначала
      `drop function if exists` **со всеми возможными старыми сигнатурами** (§2)
- [ ] Если меняю набор колонок существующей функции — **вернулся в её раннюю
      миграцию и поставил drop и там**. Без этого повторный прогон
      `setup_all.sql` поверх живой базы упадёт с 42P13 (§2)
- [ ] Если старая редакция читает колонку, которую эта миграция удаляет, —
      обернул её создание в условный `do`-блок, а не просто добавил drop (§2)
- [ ] Разовый бэкфилл заперт условием, которое не выполнится второй раз (§13)
- [ ] Если значения бэкфилла зависят друг от друга — это цикл, а не один
      `update` (§14)
- [ ] `alter publication … add table` завёрнут в проверку `pg_publication_tables` (§9)

## Права

- [ ] После `drop function` заново выданы `revoke` + `grant` (§2)
- [ ] Для новой функции решено, кому `EXECUTE`: `authenticated`,
      `service_role` или **никому** (зовут только триггеры)
- [ ] Новое представление получило явный `revoke … from anon, authenticated` (§10)
- [ ] Не появилось политики, разрешающей больше, чем нужно; там, где команда
      должна быть закрыта, политики **нет вовсе** (§11)

## RLS

- [ ] Внутри политики нет прямого подзапроса к таблице с RLS — только
      `SECURITY DEFINER`-функция (§4)
- [ ] Политика не зовёт функцию, читающую ту же таблицу (§5)
- [ ] Если правило добавлено в RPC — оно добавлено **и в политику таблицы**;
      проверил `grep -rn "\.from('таблица')" src api` (§12)
- [ ] Право проверяется на всех командах, а не только на INSERT (§22)

## Триггеры и функции

- [ ] Имя триггера даёт нужный порядок: BEFORE → INSTEAD OF → AFTER, внутри
      группы — по алфавиту (§6)
- [ ] Не полагаюсь на `auth.uid()` как на признак «пишет сервер» (§7)
- [ ] Ни одно тело PL/pgSQL не читает колонку, которую эта миграция удаляет —
      прогнал `grep` по всем `create function` (§8)
- [ ] Удаляю колонку? Прошёлся по **всем более ранним миграциям**: то, что её
      читает или пишет, обёрнуто в условный `do`-блок (§28)
- [ ] `search_path = public` не мешает: не зову ничего из схемы `extensions` (§1)
- [ ] `on conflict` по частичному индексу повторяет его `where` (§16)

## Данные и производительность

- [ ] Уникальность по неупорядоченной паре, если строка симметрична (§18)
- [ ] Под каждый счёт «сколько строк за час» есть индекс `(user_id, created_at)`
- [ ] Условие запроса записано в той же форме, что и индекс
      (`least/greatest`, `union all` вместо `or`) (§19)
- [ ] Пагинация по дописываемому сверху списку — keyset, не offset (§20)
- [ ] Ни один `select` не отдаёт строки там, где нужен счётчик (§21)

## Сборка и выкладка

- [ ] Файл дописан в `SOURCES` в `scripts/build-setup-all.mjs` — **в конец**
- [ ] `npm run sql:verify` проходит (сборка, каталог, статическая проверка)
- [ ] Решён порядок деплоя: миграция **сужает** доступ → фронтенд выкладывают
      первым; **добавляет** возможность → SQL первым
- [ ] Фронтенд переживает обе версии базы (`isMissingRelation` /
      `isMissingColumn` в `src/lib/supabase.js`)
- [ ] Написана шапка: что ломается сегодня, почему чиним так, что произойдёт с
      существующими данными
- [ ] Если миграция что-то удаляет безвозвратно — это названо в шапке прямо
